## 一、文档体系总览（现状）

CB UI 文档站的文档体系分为三个区，对应顶部导航：

```
┌─────────────────────────────────────────────────────────────┐
│                      CB UI 文档站（VitePress）                │
├─────────────────────────────────────────────────────────────┤
│                                                             │

│  ├── 介绍（intro）          —— 组件库定位与核心特性          │
```

- 首次接触：指南「介绍」→「快速上手」→ 组件列表

### 3.3 PRD 文档结构

四篇 PRD 均采用"**现状版**"写法：`文档头（版本/状态）+ 阅读提示 + 章节（现状 vs 规划标注）+ 结论先行`，方便读者快速判断"已落地 / 仅参考 / 规划中"。

## 四、文档与代码的同步机制（现状）

| 环节           | 机制                                                | 失效场景与处理                 |
| -------------- | --------------------------------------------------- | ------------------------------ |
| 组件入口       | `pnpm gen:index` 自动重写 `src/index.ts`            | 目录缺 index.ts 则不扫描       |
| 侧边栏组件列表 | `config.ts` 扫描 `docs/components/*.md` frontmatter | **新增 md 需重启 dev** 才拾取  |
| 侧边栏分类     | 三集合（BASE_SUBGROUPS / MEDIA_TOOL / BUSINESS）    | 未登记组件自动进「未分组」兜底 |
| API 表格       | `pnpm extract:props` 生成草稿 → 人工校对            | 缺 JSDoc 的字段草稿为空        |
| 新增组件文档   | 《新组件开发》验证链 7 步                           | 跳过则文档/测试缺失            |
| 文档站构建     | 先停 dev → `pnpm build:docs`（共用 .temp，需互斥）  | 不互斥则构建报错               |

## 七、附录

### 7.1 文档存放位置（现状）

| 文档类型   | 存放位置                                  |
| ---------- | ----------------------------------------- |
| 指南文档   | `docs/guide/`                             |
| 组件文档   | `docs/components/`                        |
| PRD 文档   | `docs/prd/`                               |
| API 草稿   | `docs/.vitepress/generated/`（gitignore） |
| 文档站配置 | `docs/.vitepress/config.ts`、`theme/`     |

### 7.2 文档格式要求

- 使用 Markdown 格式（.md），中文标题
- 代码块必须标注语言
- API 表格包含属性/说明/类型/默认值四列
- **禁止在代码块内嵌套代码块标记**（历史踩坑：报 `Element is missing end tag`，外层需用 4 反引号围栏）
- 侧边栏标题取自 frontmatter `title`，与文档 H1 保持一致
