## 一、选型目标

为 CB UI 组件库文档站项目选择合适的技术栈，需满足以下目标：

| 目标     | 说明                                       |
| -------- | ------------------------------------------ |
| 开发效率 | 技术栈成熟稳定，开发体验流畅，减少重复工作 |
| 性能优先 | 文档站加载快，组件渲染性能好               |
| 类型安全 | 完善的 TypeScript 支持，减少运行时错误     |
| 易于维护 | 代码结构清晰，文档与代码同步，便于长期维护 |
| 社区活跃 | 技术栈有活跃的社区支持，问题易解决         |

### 架构说明

CB UI 采用 **分层架构** 设计：

| 层级           | 技术                    | 职责                                                    |
| -------------- | ----------------------- | ------------------------------------------------------- |
| **业务层**     | CB UI 组件              | 基于 TDesign 二次封装，统一 Cb 前缀、统一主题、简化 API |
| **基础组件层** | TDesign                 | 腾讯开源企业级设计系统，提供 60+ 基础组件               |
| **框架层**     | Vue 3 + TypeScript      | 组件实现框架与类型系统                                  |
| **工具层**     | Vite 8.1、VitePress 1.6 | 组件构建与文档站                                        |
| **样式层**     | TailwindCSS + Sass      | 原子样式与复杂样式方案                                  |

### 关于 Vite 双版本（容易混淆，重点说明）

| 位置                     | 版本            | 用途                                                    |
| ------------------------ | --------------- | ------------------------------------------------------- |
| `packages/components`    | Vite **8.1.5**  | 组件库 lib 构建（vite build + vite-plugin-dts）         |
| `docs`（VitePress 内置） | Vite **5.4.21** | 文档站 dev / build，由 vitepress 依赖锁定，**勿手动改** |

两处互不干扰；改组件构建配置看组件包，改文档站构建看 VitePress。

## 三、核心技术选型详解

### 3.1 组件实现框架：Vue 3

#### 选型理由

| 对比维度        | Vue 3                  | React              | Angular    |
| --------------- | ---------------------- | ------------------ | ---------- |
| 学习曲线        | 低，API 直观           | 中等，需理解 Hooks | 高，概念多 |
| TypeScript 支持 | 原生支持，体验极佳     | 需额外配置         | 原生支持   |
| 模板语法        | 模板 + JSX/TSX 可选    | 仅 JSX             | 模板       |
| 响应式原理      | Proxy 响应式，自动追踪 | setState 手动触发  | Zone.js    |
| 团队熟悉度      | 高                     | 中                 | 低         |

#### 最终选择：Vue 3（已落地，3.5.40）

1. 团队已有 Vue 技术栈积累，学习成本低
2. Composition API 提供更好的逻辑复用与类型推导
3. VitePress 原生基于 Vue，文档站可直接渲染 Vue 组件
4. 组件支持 `<script setup lang="tsx">`（`config.ts` 已配 `jsxImportSource: 'vue'`）

---

### 3.2 类型系统：TypeScript 5.9.3

#### 优势

| 优势           | 说明                                |
| -------------- | ----------------------------------- |
| 编译时类型检查 | 提前发现类型错误，减少运行时 Bug    |
| IDE 智能提示   | 组件 Props、API 自动提示            |
| 代码即文档     | types.ts JSDoc → extract:props 提取 |
| 重构安全       | 类型约束保证重构不影响调用方        |

#### TypeScript 配置要点（实际生效）

> 多包结构使用 `tsconfig.base.json` 继承 + 各包 `tsconfig.json` 覆盖。

```jsonc
// tsconfig.base.json（节选）
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "preserve",
    "jsxImportSource": "vue",
    "declaration": true,
    "noEmit": true, // 根 tsconfig 必须关闭产物输出，否则 tsc 会把声明写到源码目录覆盖输入文件（历史踩坑：TS5055）
  },
}
```

::: warning 历史教训（TS5055）
根 `tsconfig.json` 曾继承 `declaration: true` 但未配 `noEmit`/`outDir`，导致 `vue-tsc` 把 `permission-tree/index.ts` 的声明输出到同目录 `index.d.ts` 覆盖输入文件。**修复：根 tsconfig 加 `noEmit: true`；类型检查一律用 `--noEmit`**。
:::

### 3.3 文档站点生成器：VitePress 1.6.4

#### 对比分析

| 对比维度      | VitePress | VuePress | Storybook    | Docsify |
| ------------- | --------- | -------- | ------------ | ------- |
| 构建工具      | Vite      | Webpack  | Webpack/Vite | 无构建  |
| Vue 组件支持  | 原生渲染  | 需配置   | 原生支持     | 不支持  |
| Markdown 扩展 | 丰富      | 基础     | 基础         | 基础    |
| 自定义主题    | 灵活      | 灵活     | 复杂         | 简单    |
| SEO 友好      | 是        | 是       | 中等         | 否      |

#### 最终选择：VitePress（已落地）

1. **原生 Vue**：DemoBlock 直接挂载真实组件
2. **自动侧边栏**：`config.ts` 读取 `docs/components/*.md` frontmatter 自动生成
3. **local search**：内置全文搜索
4. **别名体系**：`@cb-ui/components` → 组件源码、`#` → 组件 src（业务 API shim）、`canvas` → stub

### 3.4 样式方案：TailwindCSS 3.4 + Sass 1.101

#### 职责划分（实际）

| 层     | 技术          | 用途                                                             |
| ------ | ------------- | ---------------------------------------------------------------- |
| 文档站 | TailwindCSS   | 演示页布局、间距、响应式（`docs/.vitepress/theme/tailwind.css`） |
| 组件库 | Sass (scoped) | 组件样式，`additionalData` 自动注入 `@cb-ui/theme/src/variables` |
| 主题   | CSS 变量      | `@cb-ui/theme/src/index.css`，`var(--td-brand-color)` 等         |

#### Sass 关键配置（已落地）

```ts
// docs/.vitepress/config.ts
css: {
  preprocessorOptions: {
    scss: {
      api: 'modern-compiler', // 消除 legacy-js-api 弃用警告，勿回退
      additionalData: `@use "@cb-ui/theme/src/variables" as *;`,
    },
  },
},
```

#### 对比分析

| 对比维度        | TDesign           | Element Plus  | Ant Design Vue  | Naive UI    |

| 定制化能力      | ✅ 高（主题定制） | 中等          | 中等            | ✅ 高       |

#### CB UI 与 TDesign 的关系（实际模式）

```
业务项目 ──复制源码──▶  CB UI（基于 TDesign 二次封装，Cb 前缀）
                            │ 依赖
                            ▼
                    TDesign（1.20.5，60+ 基础组件）
```

**不发布 npm 包的原因（现状确认）**：

| 原因       | 说明                                   |
| ---------- | -------------------------------------- |
| 内部使用   | 主要供团队内部使用，无公开发布需求     |
| 灵活定制   | 不同项目定制需求不同，复制源码更灵活   |
| 维护成本低 | 无需维护 npm 版本、changelog、发布流程 |
| 快速迭代   | 组件修改后复制即用，无需等待发布       |

### 3.9 单元测试：Vitest 3.2.7 + @vue/test-utils + happy-dom

| 对比维度   | Vitest          | Jest       |
| ---------- | --------------- | ---------- |
| Vite 集成  | 原生            | 需配置     |
| 启动速度   | 快（复用 Vite） | 中         |
| TypeScript | 原生支持        | 需 ts-jest |
| Vue 测试   | 官方推荐        | 需配置     |

**当前规模**：44 files / 240 tests 全绿。

**happy-dom 环境已知坑位**（写测试前必读，详见《组件开发指南》）：

- `navigator.clipboard` 需 `Object.defineProperty` 覆盖
- t-popup 类弹层 stub 必须渲染 `<slot />` 默认插槽
- 异步初始化组件断言前等 50ms
- stub 模板禁止 TS 断言

## 六、技术选型结论

| 层级       | 技术                   | 说明                                  |
| ---------- | ---------------------- | ------------------------------------- |
| 底层组件库 | **TDesign 1.20.5**     | 基于 TDesign 二次开发，企业级基础组件 |
| 组件实现   | **Vue 3.5 + TS 5.9**   | 组件框架与类型系统                    |
| 文档站点   | **VitePress 1.6**      | 文档站生成器，自动侧边栏 + DemoBlock  |
| 样式方案   | **TailwindCSS + Sass** | 文档站原子样式 + 组件 Sass 变量       |
| 构建工具   | **Vite 8.1**           | 组件库 lib 构建 + 类型声明            |
| 包管理     | **pnpm 9**             | Monorepo 包管理                       |
| 版本管理   | **Changesets**         | 已配置，发布流程未启用                |
| 单元测试   | **Vitest 3.2**         | 44 files / 240 tests 全绿             |

### 核心特性（现状）

1. **基于 TDesign 二次开发**：依赖 `tdesign-vue-next`，提供企业级组件支持
2. **不发布 npm 包**：复制源码方式，灵活定制、快速迭代
3. **统一 Cb 前缀**：组件命名统一 `Cb` 前缀 + kebab-case 目录
4. **工程化闭环**：脚手架生成 → 自动入口 → 自动侧边栏 → 单测 → 验证链
5. **双 Vite 分工**：组件构建 8.1 / 文档站 5.4（VitePress 内置），互不干扰
