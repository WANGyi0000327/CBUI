## 一、选型目标

为 CB UI 组件库文档站项目选择合适的技术栈，需满足以下目标：

| 目标 | 说明 |
|---|---|
| 开发效率 | 技术栈成熟稳定，开发体验流畅，减少重复工作 |
| 性能优先 | 文档站加载快，组件渲染性能好 |
| 类型安全 | 完善的 TypeScript 支持，减少运行时错误 |
| 易于维护 | 代码结构清晰，文档与代码同步，便于长期维护 |
| 社区活跃 | 技术栈有活跃的社区支持，问题易解决 |

### 架构说明

CB UI 采用 **分层架构** 设计：

| 层级 | 技术 | 职责 |
|---|---|---|
| **业务层** | CB UI 组件 | 基于 TDesign 二次封装，统一 Cb 前缀、统一主题、简化 API |
| **基础组件层** | TDesign | 腾讯开源企业级设计系统，提供 60+ 基础组件 |
| **框架层** | Vue 3 + TypeScript | 组件实现框架与类型系统 |
| **工具层** | Vite 8+、VitePress | 构建工具与文档站 |
| **样式层** | TailwindCSS + Sass | 原子样式与复杂样式方案 |

## 三、核心技术选型详解

### 3.1 组件实现框架：Vue 3

#### 选型理由

| 对比维度 | Vue 3 | React | Angular |
|---|---|---|---|
| 学习曲线 | 低，API 直观 | 中等，需理解 Hooks | 高，概念多 |
| TypeScript 支持 | 原生支持，体验极佳 | 需额外配置 | 原生支持 |
| 模板语法 | 模板 + JSX 可选 | 仅 JSX | 模板 |
| 响应式原理 | Proxy 响应式，自动追踪 | setState 手动触发 | Zone.js |
| 包体积 | ~10KB（runtime） | ~40KB | ~60KB |
| 团队熟悉度 | 高 | 中 | 低 |

#### 最终选择：Vue 3

**理由：**
1. 团队已有 Vue 技术栈积累，学习成本低
2. Vue 3 Composition API 提供更好的逻辑复用与类型推导
3. VitePress 原生基于 Vue，文档站可直接渲染 Vue 组件
4. 响应式系统性能优于 Vue 2，适合复杂组件状态管理

---

### 3.2 类型系统：TypeScript 5.4+

#### 选型理由

| 优势 | 说明 |
|---|---|
| 编译时类型检查 | 提前发现类型错误，减少运行时 Bug |
| IDE 智能提示 | 组件 Props、API 自动提示，开发体验好 |
| 代码即文档 | 类型定义自动生成 API 文档 |
| 重构安全 | 类型约束保证重构不影响调用方 |

#### TypeScript 配置要点

```json

  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "preserve",
    "declaration": true,
    "declarationMap": true
  }
}
```

### 3.3 文档站点生成器：VitePress 1.x

#### 对比分析

| 对比维度 | VitePress | VuePress | Storybook | Docsify |
|---|---|---|---|---|
| 构建工具 | Vite | Webpack | Webpack/Vite | 无构建 |
| 启动速度 | 极快（毫秒级） | 慢（秒级） | 中等 | 快 |
| Vue 组件支持 | 原生渲染 | 需配置 | 原生支持 | 不支持 |
| Markdown 扩展 | 丰富 | 基础 | 基础 | 基础 |
| 自定义主题 | 灵活 | 灵活 | 复杂 | 简单 |
| SEO 友好 | 是 | 是 | 中等 | 否 |
| 社区活跃度 | 高 | 中 | 高 | 低 |

#### 最终选择：VitePress

**理由：**
1. **开发体验极佳**：基于 Vite，热更新毫秒级响应
2. **原生 Vue 支持**：文档中直接使用 Vue 组件，无需额外配置
3. **Markdown 增强**：支持容器、代码组、代码复制等功能
4. **SEO 友好**：静态 HTML 渲染，搜索引擎可抓取
5. **主题定制灵活**：可扩展默认主题，或完全自定义

### 3.5 底层组件库：TDesign

#### 选型背景

CB UI 是基于 TDesign 二次开发的个人组件库，底层依赖 `tdesign-vue-next`。选择 TDesign 作为底层组件库的原因如下：

#### 对比分析

| 对比维度 | TDesign | Element Plus | Ant Design Vue | Naive UI |
|---|---|---|---|---|
| 企业级设计 | ✅ 腾讯出品，企业级 | ✅ 饿了么出品 | ✅ 蚂蚁金服出品 | ✅ 个人维护 |
| TypeScript 支持 | ✅ 原生支持 | ✅ 支持 | ✅ 支持 | ✅ 原生支持 |
| 组件数量 | 60+ | 80+ | 60+ | 80+ |
| 设计系统完善度 | ✅ 完整设计规范 | 中等 | ✅ Ant Design 规范 | 中等 |
| Vue 3 支持 | ✅ 原生支持 | ✅ 原生支持 | ✅ 原生支持 | ✅ 原生支持 |
| 树摇支持 | ✅ 支持 | ✅ 支持 | ✅ 支持 | ✅ 支持 |
| 定制化能力 | ✅ 高（支持主题定制） | 中等 | 中等 | ✅ 高 |

#### 最终选择：TDesign

**理由：**
1. **企业级设计系统**：腾讯开源，设计规范完善，适合业务场景
2. **TypeScript 友好**：原生 TypeScript 支持，类型定义完善
3. **组件丰富**：60+ 基础组件，覆盖常见业务场景
4. **定制化能力强**：支持主题定制、样式变量覆盖
5. **社区活跃**：持续维护，文档完善，问题易解决

#### CB UI 与 TDesign 的关系

```
                        ↑ 复制代码
┌─────────────────────────────────────────────────────────────┐
│                      CB UI                                   │
│  基于 TDesign 二次封装：                                      │
│  - 统一 Cb 前缀命名                                          │
│  - 统一样式主题                                              │
│  - 简化 API 设计                                             │
└─────────────────────────────────────────────────────────────┘
                        ↑ 依赖
┌─────────────────────────────────────────────────────────────┐
│                     TDesign                                  │
│  腾讯开源企业级设计系统，提供 60+ 基础组件                     │
└─────────────────────────────────────────────────────────────┘
```

#### 不发布 npm 包的原因

| 原因 | 说明 |
|---|---|
| 内部使用 | 主要供个人/团队内部使用，无公开发布需求 |
| 灵活定制 | 不同项目可能有不同的定制需求，复制代码更灵活 |
| 维护成本低 | 无需维护 npm 包版本、changelog、发布流程 |
| 快速迭代 | 组件修改后可直接使用，无需等待发布和更新 |

### 3.6 构建工具：Vite 8.x

#### 选型理由

| 对比维度 | Vite 8.x | Webpack | Rollup |
|---|---|---|---|
| 开发启动 | 毫秒级（ESM） | 秒级（打包） | 不适用 |
| 热更新 | 快（毫秒级） | 慢（秒级） | 不适用 |
| 生产构建 | Rollup | Webpack | Rollup |
| 配置复杂度 | 低 | 高 | 中 |
| 生态兼容性 | 高 | 极高 | 高 |
| 最新特性 | ES 模块标准改进 | 成熟稳定 | 成熟稳定 |

#### 最终选择：Vite 8.x

**理由：**
1. **开发体验好**：ESM 原生支持，无需打包即可启动
2. **配置简单**：零配置可用，插件生态丰富
3. **生产构建优**：内置 Rollup，输出体积小
4. **与 Vue 深度集成**：官方推荐，插件支持完善
5. **最新特性支持**：Vite 8 提供更好的 ES 模块标准和性能优化

### 3.7 包管理器：pnpm 9.x

#### 对比分析

| 对比维度 | pnpm | npm | yarn |
|---|---|---|---|
| 磁盘占用 | 低（硬链接） | 高 | 高 |
| 安装速度 | 快 | 中 | 快 |
| Monorepo 支持 | 原生 Workspace | 需 workspaces | 需 workspaces |
| 依赖隔离 | 严格（幽灵依赖不可用） | 宽松 | 宽松 |
| 幽灵依赖问题 | 解决 | 存在 | 存在 |

#### 最终选择：pnpm

**理由：**
1. **Monorepo 友好**：原生 Workspace 支持，配置简单
2. **磁盘节省**：硬链接共享依赖，节省 50%+ 空间
3. **依赖安全**：严格依赖解析，避免幽灵依赖
4. **安装速度快**：并行安装 + 链接策略

## 五、技术风险评估

| 风险 | 风险等级 | 应对措施 |
|---|---|---|
| VitePress 版本更新可能带来 Breaking Changes | 中 | 锁定主版本，定期跟进 Release Notes |
| TailwindCSS 与 Sass 样式冲突 | 低 | 明确职责边界，Tailwind 负责 token，Sass 负责组件样式 |
| Monorepo 包依赖管理复杂 | 中 | 使用 pnpm Workspace，Changesets 统一版本管理 |
| TypeScript 类型定义维护成本 | 低 | 使用 JSDoc 注释 + 自动生成，减少手动维护 |
| TDesign 版本更新可能影响 CB UI 组件 | 中 | 锁定 TDesign 主版本，测试升级影响后再更新 |
| Vite 8.x 新版本稳定性 | 低 | 关注 Vite 官方发布说明，测试环境验证后再升级 |
| 不发布 npm 包导致组件更新同步问题 | 低 | 提供组件更新通知机制，文档记录变更日志 |

## 六、技术选型结论

综合考虑团队技术栈、项目需求、生态成熟度与长期维护成本，最终技术栈确定为：

| 层级 | 技术 | 说明 |
|---|---|---|
| 底层组件库 | **TDesign** | 基于 TDesign 二次开发，提供企业级基础组件 |
| 组件实现 | **Vue 3 + TypeScript** | 组件框架与类型系统 |
| 文档站点 | **VitePress** | 文档站生成器 |
| 样式方案 | **TailwindCSS + Sass** | 原子样式与复杂样式方案 |
| 构建工具 | **Vite 8+** | 最新构建工具，性能优化 |
| 包管理 | **pnpm** | Monorepo 包管理 |
| 版本管理 | **Changesets** | 版本管理工具 |
| 单元测试 | **Vitest** | 单元测试框架 |

### 核心特性

1. **基于 TDesign 二次开发**：底层依赖 `tdesign-vue-next`，提供企业级组件支持
2. **不发布 npm 包**：采用复制组件代码方式，灵活定制，快速迭代
3. **统一 Cb 前缀**：组件命名统一使用 Cb 前缀，便于识别和管理
4. **最新 Vite 8+**：采用最新构建工具，提供更好的开发体验和性能

该技术栈组合具备开发效率高、类型安全、性能优秀、易于维护的特点，能够支撑 CB UI 组件库文档站的长期发展。
